# Security Policy

## Supported versions

Security fixes are applied to the latest released version and the current `main` branch.

Older releases may not receive backported fixes.

## Reporting a vulnerability

Please **do not open a public GitHub issue** for a vulnerability that could expose authentication tokens, bypass 2FA, execute commands without authorization, escape file restrictions, or otherwise compromise a user's system.

Preferred reporting method:

1. Open this repository's **Security** tab.
2. Use **Report a vulnerability** / private vulnerability reporting if it is available.
3. Include enough detail to reproduce the issue safely.

If private vulnerability reporting is not available, open a minimal public issue asking the maintainer for a private contact channel, but do not include exploit details, secrets, or proof-of-concept payloads in the public issue.

A useful report includes:

- affected version or commit;
- affected platform;
- reproduction steps;
- expected vs. actual behavior;
- security impact;
- suggested mitigation, if known.

Please avoid destructive testing against systems you do not own or have permission to test.

## Disclosure

Please allow reasonable time for investigation and a fix before public disclosure.
